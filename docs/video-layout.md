# 视频宽高比适配与验收

最新调整：评论已替换为只读故事。公共页头、侧栏与推荐页只按视口宽高比切换桌面／手机布局：宽度不大于高度（≤1:1）使用手机版，其余使用桌面版。故事在两种布局下都只覆盖背景，绝不参与播放器排版。剧场模式已移除，全屏保留。下方「历史实现与验收」中的评论、手机底部面板与剧场描述均为旧版记录。

## 推荐页当前布局规则

- 公共页头、侧栏、播放区、故事弹窗与翻页控件共用 1:1 分界。移除宽度触发的自动折叠、搜索框重定位、品牌尺寸切换，以及超宽屏标题移到播放器外的容器断点。
- **电脑端**：侧栏默认展开为 240px，可手动折叠为 72px；用户选择不随宽度跳变。翻页按钮固定 56px，距右边 24px；故事弹窗距右边固定 96px。搜索框只连续伸缩，不再在 1200px 改变定位方式。
- **手机版**：隐藏常驻侧栏、使用菜单浮层和搜索按钮，故事入口叠在播放器内，上下切换按钮隐藏。故事弹窗在视口中央覆盖原视频。
- **故事覆盖层**：使用原生 `dialog.showModal()`，电脑端靠右、手机版居中。背景控件由浏览器隔离，Tab 留在弹窗内，Escape、关闭按钮或点击遮罩关闭后恢复故事入口焦点。删除 `has-story` 布局类及其缩小、偏移规则，比例函数不再接收故事开关；两种布局下均不会重排背景视频。
- 旧断点扫描：电脑端宽度 600、601、791、792、999、1000、1100、1199、1200、1311、1312、1799、1800、2299、2300 均保持上述固定规则；手机竖向视口宽度 320–1800 共 12 组同样一致。实际 CSSOM 中没有任何独立宽度媒体规则匹配推荐页元素。首页网格、观看页正文仍有各自的局部排版规则，不参与推荐页或公共导航布局。
- 覆盖层验收：1280×720、600×400、700×950、390×844、800×800、801×800，分别比较打开前／打开后／关闭后的播放器位置、宽高、当前视频、暂停时间与滚动位置，全部严格一致且无横向溢出。例如 700×950 的 3:4 视频始终为 670.5×894，位置 (14.75, 56)；1280×720 始终为 468×624，位置 (478, 64)。
- 手动折叠跨越 1312/1311、792/791 和 600px 后仍为 72px；手机菜单、搜索展开后跨到电脑布局会正确收起浮层。浏览器警告和错误日志为空，10 项有效测试与生产构建通过（移除了已废弃的「故事强制竖屏」断言）。

## 历史实现与验收

2026-09-20。依据用户的四张 YouTube 截图及实际网站交互实现；本规则取代此前已回退的推荐页比例尝试。

## 用户要求与实现

1. 首页所有视频共用 16:9、12px 圆角封面，包括手机端。封面用 `cover` 填满，视频的原始比例不会改变列表行高。
2. 观看页读取 `videoWidth/videoHeight`。横屏播放器按原比例布局，最大高度为视口高度减 116px；桌面内容列同步限制宽度并居中。方形、竖屏保留标题和评论所需的列宽，画面完整居中。剧场与全屏继续完整显示画面。
3. 推荐页以 9:16 为默认框，媒体加载后在 9:16–1:1 之间适配。3:4 使用 3:4；方形或横屏使用 1:1；更窄的竖屏仍放入 9:16。打开评论后所有视频都使用 9:16，宽视频上下留黑；关闭后恢复该视频的比例。
4. 评论仅改变布局，不替换播放器 DOM，不重置播放、暂停、音量或进度。固定高度的推荐项保留滚动吸附与当前项。
5. 小屏评论使用底部面板；9:16 播放框缩放到面板上方，避免整个有效画面被面板挡住。此时面板继续接管焦点，背景控件不可操作，关闭后恢复。

尺寸来源是媒体元数据，不依赖文件名、封面尺寸或手填横竖屏字段。监听 `loadedmetadata` 和视频 `resize`；挂载时检查已缓存的元数据，避免事件在 hydration 前触发后丢失。未知尺寸先使用默认框，实际播放始终使用 `object-fit: contain`。
