# 真实视频导入准备

用户已要求完成上传前全部准备。网站仅供浏览；媒体由站长经 SSH/SCP/rsync 直接传到服务器，不提供网页上传、账户管理或写入 API。沿用现有布局及 PostgreSQL，媒体与发布目录分离，不开通 COS。

## 存储与导入

生产根目录 `/srv/bnds-life/media`，含私有 incoming、originals、.work 和公开 playback、posters。Nginx 仅映射 `/media/playback/` 与 `/media/posters/`，支持 Range；原片和待处理文件不得由 HTTP 访问。媒体路径只记录相对路径，不绑定网站域名。

命令行提供 doctor、migrate、import、batch、list、edit、publish、hide。显式指定待导入文件，默认草稿；批量清单含文件、标题、可选拍摄日期、故事、封面。导入串行处理，保留原文件名和 SHA256，以原片哈希去重；失败文件不发布，可重试。默认保留上传文件，只有显式 --consume 才在完整性复核和成功入库后清理 incoming 内的同一文件。

先探测文件，保留原片。浏览器适用的 MP4/H.264/yuv420p/AAC 且码率、尺寸、帧率适中，先重封装清理公开元数据，只有结果字节与原片完全一致时才复用原片文件。不兼容或高码率素材按需转为 H.264/AAC、最长边不超过 1920、CRF 20，最多 2 个线程。短边不放大，保留宽高比并处理旋转。HDR 不自动当 SDR 发布，报告需要专门处理。封面由 FFmpeg 自动截取代表画面，可显式指定封面；失败使用默认图片，不伪造内容。

落盘采用唯一临时目录和最终原子改名；全局导入锁防并发碰撞，进程退出释放锁。可用空间必须在估算处理需求之外保留 10 GiB。媒体就绪后数据库事务写入；失败不会留下可见的半条视频。业务失败可清理本次生成的临时目录，不清理用户原片。

## 数据库与网页

新增 videos 和 video_assets，使用独立、幂等、事务式 SQL 迁移，不修改账户表。videos：UUID、标题、故事、拍摄日期（YYYY / YYYY-MM / YYYY-MM-DD 或 null）、草稿/发布/隐藏、原片 SHA256、发布和维护时间。video_assets：UUID、所属视频、original/playback/poster、相对路径、原文件名、字节数、SHA256、宽高、毫秒时长、MIME、处理方式、探测元数据和创建时间；同一视频同种资源唯一。

站点只查询已发布条目，并且要求播放文件与封面资源记录齐全。公开 API 只输出现有 Video DTO，不输出原片路径、原文件名或探测元数据。数据库连接继续复用现有 Drizzle。demo/database 两种目录模式显式配置；生产切到 database，暂无真实素材时显示简洁空状态。开发默认 demo。导入后页面立即可读，无需重新构建或重启；观看页不再预生成固定目录。首页支持精确到月的拍摄日期，未知年月归入待补充；上传时间不冒充拍摄时间。

## 验收

真实 FFmpeg 夹具验证复用、重封装、转码、自动封面、坏文件、重复导入、空间不足、日期校验；独立数据库 schema 中验证迁移、发布/隐藏和原片信息隔离。生产仅做空目录和私有演练，不将测试视频发布到公网。确认 HTTPS Range、原片拒绝访问、站点三个入口、导入工具和数据库备份可恢复。

## 运维约束

已检查服务器约 151 GiB 可用。几百段原片加播放文件可能超出磁盘，doctor 每次报告实际容量，批量导入逐个预检。备份脚本保存数据库和媒体清单至私有目录；同盘备份不能替代用户本地原片或异地备份。今后传输保持本地原片。所有服务器配置、发布和验证均经 SSH。
