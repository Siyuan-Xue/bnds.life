# 首版验收记录

日期：2026-09-20。环境：macOS、Codex 内置浏览器、Node.js 26.9.0、pnpm 12.4.2、Next.js 15.5.25、OrbStack、PostgreSQL 18.6。

## 启动与数据

- 用户自行完成 OrbStack 首次设置；通过现有 `./start-database.sh` 启动 PostgreSQL。
- `pnpm db:push` 成功；数据库包含 `user`、`session`、`account`、`verification` 四张表。
- 修正脚手架中未使用的 GitHub OAuth 必填变量和数据库表过滤范围。
- 重复执行启动脚本成功复用容器。修复之前会因容器已占用 5432 端口而误报。
- 公开页面直接使用共同的占位目录，浏览不依赖登录。真实视频、评论及个性化推荐尚未接入数据库。

## 浏览器交互

- 首页直接显示 12 条占位视频；侧栏只有首页与推荐。展开、折叠、窄屏遮罩菜单均可操作。
- 搜索「操场」返回两条视频；手机 200 字符查询不再造成横向溢出。
- 点击封面进入对应观看页，浏览器返回可恢复列表的滚动位置。
- 播放/暂停、静音切换、拖动进度、1.5 倍速、剧场模式均检查了实际媒体或布局状态。
- 全屏按钮切换为退出全屏，播放器占满 1440×900 视口；退出后恢复。剧场模式播放器为 1440×675，顶部 y=56，页面 scrollY=0。
- 推荐初始项为 memory-02，下一项为 memory-05；切换后旧视频暂停，只有当前项播放。鼠标滚动、桌面切换按钮和手机滚动已操作验证。
- 评论面板、排序、展开回复、账户提示均可交互。手机评论面板限制焦点，关闭后恢复触发按钮焦点。
- 登录提示中的 Escape 只关闭当前提示，不会同时关闭底下的评论面板。
- 未知视频地址显示中文「没有找到这段回忆」。本轮本地浏览器错误日志为空。

## 参考布局与响应式

对照用户截图及实际访问的 YouTube 页面测量，已删除未确认的功能控件。坐标单位为 CSS 像素。

| 场景                   | 参考与实现的关键测量                                                   |
| ---------------------- | ---------------------------------------------------------------------- |
| 1440×900 首页展开侧栏  | 顶栏 56；侧栏 240；第一张封面 x=264、y=136、宽约373.33；三列，列间距16 |
| 1440×900 观看页        | 播放器 x=16、y=68、996×560.25；右栏 x=1028、宽396                      |
| 1440×900 推荐展开侧栏  | 播放区域 x=565.875、y=64、452.25×804                                   |
| 1920×1080 推荐展开侧栏 | 播放区域 x=755.25、y=64、553.5×984；标题区左移到 x=256、宽480          |
| 1920×1080 首页         | 四列；折叠侧栏参考缩略图宽438，列间距16                                |

首页、观看页、推荐页分别检查 390×844、768×1024、1024×768、1440×500、1920×1080，15 组均无文档横向溢出。手机侧栏隐藏时内容从 x=0 开始。推荐页在空间不足时将标题叠在视频底部，手机评论使用底部面板。

这些是本次实际检查的视口，不代表所有浏览器、所有尺寸的逐像素保证。YouTube 存在地区及实验版本差异；没有实机检查 iOS/Safari，也没有模拟浏览器拒绝自动播放及媒体断网。代码提供播放按钮与加载失败重试作为相应回退。

## 自动检查与审查

- `pnpm test`：4 项测试，覆盖目录搜索、未知 ID、共用目录/推荐去重、修饰键快捷键防误触。
- `pnpm check`：ESLint 与 TypeScript 通过，无 lint 警告或错误。
- `pnpm build`：生产构建通过，生成17个页面；`pnpm start` 成功启动并实际访问首页。
- 独立代码审查未发现 Critical 问题；搜索溢出、组合键、叠层 Escape、手机评论焦点问题均已修复并验证。

账户架构保留，登录方式与真实评论发布按用户选择延后。所有视频为本地生成的占位文件，评论明确标注示例。本次交付本地开发版与 GitHub 代码，尚未部署到域名或服务器。

代码已推送到私有仓库 [Siyuan-Xue/bnds.life](https://github.com/Siyuan-Xue/bnds.life)，主分支为 main。`.env` 和本地密钥未包含在提交中。

## 推荐播放框自适应调整（2026-09-20）

- 用户要求保留默认竖屏，但允许播放框按实际视频比例适度调整，提高有效画面占比。
- 使用视频原生 `videoWidth/videoHeight`，将框的宽高比限制在 9:16 至 1:1；竖屏沿用原布局，较宽内容扩大，窄屏按可用宽高收缩。继续使用 contain，完整显示画面。
- 保持每条推荐的滚动高度，调整只发生在条目内部。扩大后的标题留在框内，避免与原竖屏的外置标题规则重叠。
- 修复缓存媒体在 React 就绪前已触发 loadedmetadata 的情况：挂载后也检查已可用的尺寸。
- 1567×994 视口的横屏素材为 960×540；调整前播放框 505.125×898，调整后 898×898，有效画面占框比例约 31.6% → 56.3%。切到 540×960 素材时恢复 505.125×898，只有当前视频播放。
- 同一桌面视口展开评论后播放框 655×655，评论面板宽480，互不重叠。
- 横屏素材检查 390×844、600×390、768×1024、1024×768、1440×500、1920×1080，均不超出可用高度，也没有横向溢出。390px 手机评论开合及滑动至竖屏视频正常，竖屏仍为 390×788。
- 本次使用浏览器中的两种真实媒体尺寸验证；未新增只镜像样式实现的单元测试。
